## Варианты тестирования

### ⚠️ Важно: Проблема с авторизацией и плагином в Docker образе

**Текущая ситуация:**
- Docker образ собран из базового образа, который не содержит новый плагин `pivot-table-v2`
- Dev-server на порту 9001 использует актуальный код с новым плагином
- Проблема с авторизацией через dev-server может быть связана с проксированием сессий

### Вариант 1: Dev-server (РЕКОМЕНДУЕТСЯ для разработки) ✅

**Текущий статус:** Dev-server запущен на порту 9001

1. **Откройте в браузере:** http://localhost:9001
2. **Войдите:** `admin` / `admin`
3. **Если возникает ошибка авторизации:**
   - Попробуйте очистить cookies браузера для localhost:9001
   - Или используйте режим инкогнито
   - Или попробуйте другой браузер

**Преимущества dev-server:**
- Использует актуальный код с новым плагином
- Hot-reload при изменениях кода
- Не требует пересборки Docker образа

### Вариант 2: Docker образ (требует пересборки базового образа)

**⚠️ Внимание:** Текущий Docker образ не содержит новый плагин, так как базовый образ был собран до добавления плагина.

Для использования плагина в Docker образе нужно:

1. **Пересобрать базовый образ с новым плагином** (требует доступа к GitLab CI/CD):
   - Обновить базовый образ в GitLab CI/CD
   - Или пересобрать локально с включенным плагином

2. **Или смонтировать frontend код и пересобрать assets внутри контейнера:**
   ```bash
   # Раскомментировать в docker-compose.dev.yml:
   # - ../superset-frontend:/app/superset-frontend:ro
   
   # Затем пересобрать assets внутри контейнера:
   docker compose -f docker/docker-compose.dev.yml exec superset_dev bash -c \
     "cd /app/superset-frontend && npm install && npm run build"
   ```

**После пересборки:**
- Откройте http://localhost:18088
- Войдите: `admin` / `admin`
- Плагин должен быть доступен
